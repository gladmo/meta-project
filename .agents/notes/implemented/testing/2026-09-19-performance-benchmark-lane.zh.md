# Agent Note: 性能基准测试通道

Status: implemented

[English](2026-09-19-performance-benchmark-lane.md) | 中文

## Problem

本脚手架验证文档、决策记录，并通过项目自身的命令验证行为，但它没有任何测量面。一次保持所有可观察行为不变、却让热点路径成本翻倍或长期持有整份输入语料的改动，能通过本仓库拥有的全部验证门。源项目用 `benchmarks/` 回答这个问题，但那棵树绑死在它自己的工具链上：Vitest 编排的 TypeScript 用例、tsdown 编译到 `.dsh-build/` 的工作负载、为基准专用依赖单设的工作区私有包，以及用 Playwright 驱动构建后客户端产物的通道。这些都无法移植到一套与语言无关、零依赖的脚手架里。

## Decision

`benchmarks/` 移植其纪律，去掉其工具链。[run.mjs](../../../../benchmarks/run.mjs) 发现 `<path>/<name>.bench.mjs` 用例，逐个在全新子进程中运行——任何测量都不与其他用例共享 CPU——并汇总每个用例打印的 JSON 报告行。用例通过 [support/worker.mjs](../../../../benchmarks/support/worker.mjs) 取样：每个样本一个全新纯 Node 进程，受期限约束，退出码、信号、超时、stderr 与报告各自独立返回。工作负载用 `assertPlainNodeWorker` 断言自身运行期——来自本目录树、无模块加载器、生产入口解析到 JavaScript 文件。输入按评审过的常量在私有的 `mkdtemp` 根目录中合成，无论成功还是失败都会删除该目录；每个用例都把实测端点计数与固定数据对照，因此漏做工作的扫描会明确失败，而不是报出一个又快又错的样本。

预算是评审过的源码常量：[support/calibration.mjs](../../../../benchmarks/support/calibration.mjs) 把 CI 时间系数与波动余量施加到参考机器时长上，对保留堆只施加余量。任何环境变量都不能覆盖预算；判定取五个样本的中位数，并与原始样本、离散程度和宿主信息一同上报。

随附的 `doc-gates` 用例测量每个 Markdown 验证门都要跑的语料扫描——`markdownFiles`、`readRel`，以及 [scripts/lib/md.mjs](../../../../scripts/lib/md.mjs) 中共享的 `analyze`——输入是 800 个文件、100,000 行的合成双语文料。验证门脚本本身只有命令行入口，因此测量边界止于分析器的输出。该用例不需要构建步骤、浏览器或任何依赖。

## Calibration evidence

参考机器：Intel Core i7-6700HQ，darwin x64，并行度 8，Node v26.7.0，V8 14.6。五次运行、每次五个全新进程样本，得到的墙钟时间中位数依次为 172.1、134.6、160.6、157.4、150.8 ms，每个样本的保留堆都是 4.50 MiB。随附期望值向上取整到观测中位数之上——175 ms 与 5 MiB——对应预算 438 ms 与 7 MiB。

2× 时间系数继承自源项目针对托管运行器的校准，而非在本地对托管运行器实测得到，因此在把任一预算当作其他机器上的保证之前，仍需一次 CI 实测。

两个探针证明判定确实会失败。像保留性回归那样持有每份文档的原文，会把保留堆样本从 4.5 MiB 推到 10.8 MiB，越过 7 MiB 预算。一个不可能达到的 3 ms 墙钟期望会让用例报出 `median wall time … exceeds budget 3 ms`，经运行器以非零退出，运行器同时报告该用例失败并自身以非零退出。

## Alternatives considered

**原样复制源项目的目录树。** 否决：TypeScript 用例、编译工作负载的构建步骤、基准专用工作区包与 Playwright 通道都与脚手架"语言无关、零依赖"的契约冲突，没有该工具链的项目会继承一棵跑不起来的树。

**只带规则、不带运行器。** 否决：写在文字里的预算无法被证伪。这些规则之所以值得携带，正是因为有一条命令执行它们，且有一份记录下来的参考让数字可以被修订。

**把通道并入 `run-gates`。** 否决：测量既慢又对宿主敏感，而 `run-gates` 必须保持确定，并便宜到可以放进提交钩子。本通道保留独立入口，正如源项目保留独立的基准 CI 作业。

**引入微基准库。** 否决：它给零依赖的脚手架加上依赖，并把真正要紧的部分——新进程隔离、期限处理与预算算术——藏到读者本来还得再学的 API 之后。

**只保留测量、不保留预算算术。** 否决：只报数字不给评审过的上限，等于把"我看着还行"当作判定，且在常量被越过时没有任何东西会失败。

## Consequences

新增一个用例的成本是固定数据、工作负载、用例文件与一组 README 文档对，其校准证据要更新到归属的笔记。新增用例的规则由 [benchmarks/AGENTS.md](../../../../benchmarks/AGENTS.md) 承载；用例循环由两个文件组成，因为用例负责编排、工作负载负责测量，把用例移植到另一种语言意味着两者都要替换。

预算的好坏取决于其来源：宿主变化需要一次新的记录运行与更新后的期望值，绝不能是放宽的常量或环境变量覆盖。本通道不运行浏览器，因此用户可见的渲染成本仍属源项目的关注范围，直到某个项目补上该通道与它的后缀。

该层级是可选的。不需要测量面的项目删除 `benchmarks/` 以及根 `AGENTS.md` 中指向它的命令行即可；其余层级从不依赖它。
