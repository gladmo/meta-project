# 文档验证门语料用例

[English](README.md) | 中文

测量每个 Markdown 验证门都要跑的那一遍语料扫描：遍历文档、逐个读取，并对文本运行 [scripts/lib/md.mjs](../../scripts/lib/md.mjs) 中共享的生产分析器。这条路径跨越归属——分析器属于验证门，语料属于文档层级——因此它的预算放在本通道，而不是放在任何一方旁边。用 `node benchmarks/run.mjs doc-gates` 运行；通道本身见 [benchmarks/README.md](../README.zh.md)。

## 负载

[synthetic-corpus.mjs](synthetic-corpus.mjs) 拥有全部评审过的常量：四个目录下共 400 组中英文文档对——800 个文件、100,000 行、10,400 个标题、38,400 条链接、800 个续行段落——外加一个依赖目录文件和一个必须被遍历忽略的 `CLAUDE.md`。中英文两侧结构完全镜像，与真实译文对一致。每份文档都在围栏代码块内藏了一行标题形状的文本和一条链接，因此丢失围栏状态的扫描会数出多于固定数据保证的数量。

[doc-gates.worker.mjs](doc-gates.worker.mjs) 把该语料写入自己的 `mkdtemp` 根目录，再把实测端点与 `expectedEndpoints()` 对照：漏掉文档或误计围栏示例的扫描会直接失败，而不是报出一个又快又错的样本。没有任何环境仓库内容、录制材料或网络服务提供输入。

## 测量

| 端点 | 边界 | 预算 |
|---|---|---|
| 墙钟时间 | 从 `markdownFiles` 到最后一次 `analyze` 调用；语料落盘、两次回收与结果上报都在边界之外 | 中位数 ≤ 438 ms（`ciTimeBudget(175)`） |
| 保留堆 | 在已解析语料仍可达时，以事件循环让步分隔的两次回收后的 `heapUsed`，减去扫描前的同项测量 | 中位数 ≤ 7 MiB（`memoryBudgetMiB(5)`） |

样本来自五个全新进程，各自拥有独立的语料根目录；判定取中位数，报告携带每个样本、离散程度与宿主信息。超过 60 秒期限的样本会被杀掉，并连同退出码、信号、超时与 stderr 一起上报。

## 排除项

测量路径止于分析器的输出。各验证门对该输出所做的处理——检查链接目标是否存在、比对文档对的标题结构、列出折行违规——都在边界之外；进程启动、`run-gates` 汇总，以及远比合成语料更小的真实仓库语料同样如此。校准来源、备选方案，以及证明判定确实会失败的探针，都由[归属的 Agent Note](../../.agents/notes/implemented/testing/2026-09-19-performance-benchmark-lane.zh.md) 承载。
